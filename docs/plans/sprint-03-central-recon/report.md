## 4. 수동 확인 (Phase 3)

### 병합 셀 → 텍스트 변환

- ✅ 의미적 병합(가상 병합) 감지: "영업분과"가 여러 행을 커버하는 경우 반복 기재
- ✅ colspan 병합: 데이터 동일 시 하나로 합침
- ⚠️ 일부 복잡 테이블(과제 재분류)에서 열 수 차이 (5열 vs GT 7열) — 데이터 자체는 보존

### 구조 보존

- ✅ To-do 시트: 리스트 형태로 변환 (GT와 동일 구조)
- ✅ Summary 시트: 12열 테이블 (GT와 동일)
- ✅ 간트차트 1Q~4Q: "진행" 상태 텍스트 반영 (GT와 정확 일치)

### 정보 손실

- ✅ AX_sample 638줄 vs GT 633줄 — 거의 동등
- ✅ 키워드 커버리지 81%+ — 핵심 비즈니스 용어 대부분 보존
- ⚠️ AX_sample 수치 커버리지 71.9% — 일부 세부 수치 누락 가능

## 6. 결론 및 권장사항

### 결론

**gpt-oss-120b (Central LLM)은 reconstruct에 실용적입니다.**

- 3개 문서 모두 ROUGE-1 F1 ≥ 0.82, 키워드 커버리지 ≥ 81%
- GT(Gemini 2.5 Flash)에 근접하는 품질
- 사내 인프라로 비용 무료

### 권장사항

1. **사내 기본 모델로 채택 가능** — 비용 절감 + 유사 품질
2. **`<br>` 후처리 추가 권장** — `reconstructor.py`에서 `<br>` → ` / ` 치환하면 확률적 변동 완전 제거
3. **복잡 테이블(AX_sample급)은 수치 커버리지 모니터링** — 71.9%로 일부 누락 가능
4. **504 Timeout 대응** — `max_workers=1` 또는 재시도 로직 강화 검토
